概述：这个技能解决什么问题？

核心使命

将一篇学术论文 PDF 自动转化为一份深入浅出的中文 HTML 详解文档，同时维护项目内多篇论文之间的知识关联图谱和交叉引用网络。

输入 → 输出

环节内容
输入1 篇学术论文 PDF（任意领域，推荐统计学/ML/计算生物学）
中间产物论文文本提取 → 结构分析 → 知识关联分析 → 详解大纲
输出(1) 论文详解 HTML (2) 更新后的知识图谱 (3) 已有论文回溯更新 (4) 项目 CLAUDE.md 更新

逐步详解

📂

Step 1 · 整理 PDF

做什么：将论文 PDF 复制到项目的 literature/ 目录Contents。

为什么：确保所有原始 PDF 集中存放，便于后续查找和维护。

命令：mkdir -p literature/ && cp paper.pdf literature/

📝

Step 2 · 提取 PDF 文本

做什么：使用 pdftotext 将 PDF 转化为纯文本。

为什么：后续的结构分析和内容理解依赖于可搜索的文本。若 PDF 加密，需用户提供无密码版本。

关键输出：文本行数（评估篇幅）+ 前 200 行（获取标题、摘要、作者等元数据）。

🔍

Step 3 · 分析论文结构

分四层分析：

  1. 元数据识别：标题、作者、期刊、年份、DOI — 用于 HTML 头部和命名
  2. 章节解析：识别引言、方法/模型、理论、实验、讨论的标准结构（论文并不总有明确标注，需要语义推断）
  3. 关键数学对象提取：每个核心公式的变量域、维度、角色、约束条件
  4. 实验与评估：识别数据生成方式、对比方法和评估指标
🔗

Step 4 · 分析知识关联

仅当项目已有其他论文时执行。这是知识图谱更新的前期准备：

  • 浏览已有论文详解 HTML 的关键章节（摘要、模型定义、理论结果）
  • 对每个核心概念做四类判断： Shared 共享 Generalizes 推广 Complements 互补 Unique 独有
  • 记录完整的概念-论文映射关系，供后续图谱更新和交叉引用使用
📋

Step 5 · 设计详解大纲

大纲必须包含：

  • §0 阅读导引：预备知识速览 + 符号约定表 + 与已有论文的关系对比表
  • §1-N 逐章详解：每个论文章节 → 一个讲解章节，覆盖背景动机、数学原理、直观理解、应用场景、延伸讨论
  • 交叉引用标记点：在何处插入 .crossref 块指向已有论文

难度递进原则：§0 几乎无公式 → §1-2 文字为主 → §3-4 逐步增加公式密度 → §5+ 完整技术细节。

✍️

Step 6 · 撰写 HTML 文档（核心步骤）

严格遵循的参考规范：

参考文件规范内容

✅

Step 7 · 验证

验证清单（7 项）：

  • MathJax 公式语法正确，HTML 标签闭合完整
  • 目录锚点链接可跳转（#sec-N）
  • 7 种标注盒恰当使用（见下文"标注盒体系"）
  • 每节有动机说明和要点总结（.summary）
  • 术语翻译与 chinese-terminology.md 一致
  • 顶部导航栏和底部相关资源栏完整
  • UTF-8 编码
🗺️

Step 8 · 更新知识图谱

5 项必更新组件：

  1. 概念关联图谱（.network-grid）：新增论文节点 + 独有概念标签 + 共享/桥梁区域调整
  2. 概念-论文对照矩阵（.matrix-table）：新增列 + 新概念行
  3. 论文间关系卡片（.rel-card）：新论文与每篇已有论文的关系描述
  4. 推荐阅读路径（.roadmap-steps）：根据需要调整顺序
  5. 更新日期 + 论文计数（.kg-header）
🔄

Step 9 · 回溯更新已有论文

为项目中所有已有详解 HTML 做增量更新：

  1. 在 .top-nav-bar 中添加新论文链接
  2. 在相关章节插入指向新论文的 .crossref 块
  3. 在 .related-bar 中添加新论文条目

核心要求：交叉引用必须自然——在概念重叠处自然地提及，而非生硬插入。例如："本节的 XXX 方法在 YYY 论文中得到了系统应用，参见..."

📄

Step 10 · 更新项目 CLAUDE.md

在"已有输出"表格中添加新论文条目，更新项目结构图，调整论文计数。

若论文扩展了项目的研究方向（如从纯 MR 拓展到 AI/ML），同步更新项目定位描述。

输出文件结构

summary/ ├── literature/ ← PDF 原文存放 │ ├── paper_1.pdf │ ├── paper_2.pdf │ └── summary/ ← HTML 输出目录 │ ├── Sanderson_2022_Mendelian_randomization_zh.html ← 详解 (按命名规范) │ ├── Cui_2025_Multimodal_foundation_models_zh.html │ └── knowledge_graph.html ← 知识图谱 (固定名称) └── CLAUDE.md ← 项目导引文件

HTML 文件命名规范

格式：{第一作者姓氏}_{年份}_{标题前三个实义词}_zh.html

规则：跳过冠词（a/an/the）、介词（of/for/in/on）、连接词（and/or），取前三个有实质意义的单词。示例：

论文标题→ 文件名
"Mendelian randomization"Sanderson_2022_Mendelian_randomization_zh.html
"Strengthening the Reporting of Observational Studies in Epidemiology using Mendelian Randomization"Skrivankova_2021_Strengthening_Reporting_Observational_zh.html
"Towards multimodal foundation models in molecular cell biology"Cui_2025_Multimodal_foundation_models_zh.html

教学标注盒体系（7 + 1 种）

这是 paper-explainer 最核心的教学基础设施。每种盒型有明确的使用场景和视觉编码。

盒型CSS 类编码使用场景示例
直观理解 .intuition 🟢 绿边 每个新概念的第一层展开——白话无公式，日常类比 "Transformer 的注意力机制就像基因之间的'通信强度'"
正式定义 .definition 🔵 蓝边 第三层展开——完整数学定义、公式、条件 Wald Ratio 估计量公式 + 符号说明
具体示例 .example 🟡 黄边 低维数字演示、具体数据场景、代码片段 "假设 SNP1 对 BMI 的效应是 0.3 SD..."
定理/结论 .theorem 🟣 紫边 定理陈述、命题、正式理论结果 "在 InSIDE 假设下，MR-Egger 给出一致估计"
算法 .algorithm ⬜ 灰边 + 等宽字体 分析工作流、伪代码、计算步骤 "推荐 MR 分析流程：IVW → 径向 MR → MR-Egger → ..."
要点总结 .summary 🔷 浅蓝边 每节末尾的关键收获（bullet 列表） "本节要点：① IV1-IV3 检验因果...② IV4 估计效应..."
注意事项 .warning 🔴 红边 局限性、常见陷阱、关键警告 "F < 10 = 弱工具，估计偏向观察性关联"
交叉引用 .crossref 📎 虚线绿边 指向其他论文的自然连接——"如果你是这么想的，那篇论文..." "详见 STROBE-MR §5 → 知识图谱 关系1"

教学策略模式（精选）

Pattern 1 · 三层展开（Three-Layer Exposition）

对每一个核心概念，提供三层递进解释：

  1. 直觉层（.intuition）：1-3 句话，0 公式，日常类比 → 目标读者：从未见过这个概念的人
  2. 半形式化层（正文）：展示公式 + 逐行注释每个符号 → 桥梁：连接直觉与精确
  3. 正式层（.definition）：完整数学定义 → 给需要精确的读者

Pattern 2 · 类比桥梁（Analogy Bridge）

将不熟悉的概念连接到熟悉的概念。例如：

新概念熟悉类比
CP 分解SVD/特征分解的推广
模-k 展开堆叠矩阵列
多级注意力（模内+模间）Swin Transformer 的分层注意力
IVW（逆方差加权）多个"微型研究"的荟萃分析

Pattern 4 · 问答驱动（Question-Answer Threading）

预判读者自然产生的问题并直接回答。核心句式：

  • "为什么不能让所有条目共享同一个非线性函数？因为..."
  • "为什么选择弹性网而不是纯 Lasso？因为张量数据的相邻条目高度相关..."
  • "所以呢？——这个定理的实践含义是..."（Pattern 6）

Pattern 3 · 具体先于抽象（Concrete-Before-Abstract）

在给出一般公式之前：

  1. 先展示一个具体的小例子（如 2×2×2 张量 + 具体数字）
  2. 再推广到任意维度
  3. 最后连接回论文的实际使用场景

HTML 骨架结构

<!DOCTYPE html> <html lang="zh-CN"> <head> <meta charset="UTF-8"> <title>[论文标题] —— 详细中文解读</title> <style>/* 完整内联 CSS：变量体系 + 7种标注盒 + 响应式 */</style> <script>/* MathJax 3 配置：inline + display + SVG 渲染 */</script> </head> <body> <!-- 1. 顶部导航栏 --> <div class="top-nav-bar">链接知识图谱、其他论文、原始PDFOriginal PDF</div> <!-- 2. 头部 --> <header>标题、作者、期刊、DOI、<div class="abstract-box">核心要义</div></header> <!-- 3. 目录Contents --> <nav class="toc">可折叠的锚点链接目录</nav> <!-- 4. 正文 — 逐节展开 --> <section id="sec-0">§0 阅读导引</section> <section id="sec-1">§1 </section> ... ← 每节末尾有 .summary + .back-top <!-- 5. 页脚 --> <footer> <div class="related-bar">所有论文链接 + 知识图谱 + 原始PDFOriginal PDF</div> </footer> </body> </html>

8 条核心质量标准

  1. 数学公式前必有直观白话解释——不能上来就甩公式
  2. 每个核心概念至少配一个具体小例子——最好用低维数字演示
  3. 理论结果后必须回答"所以呢？"——实践含义、建模选择、样本需求
  4. 术语首次出现时附英文原文——"孟德尔随机化（Mendelian Randomization, MR）"
  5. 章节间有逻辑过渡句——"理解了 X 之后，下一个自然的问题是 Y..."
  6. 全文术语翻译统一——严格参照 chinese-terminology.md
  7. 交叉引用自然——在合适上下文自然提及，非生硬插入
  8. 知识图谱完整——每次新增论文后同步更新所有组件

反模式（避免）

  • ❌ 以一个正式定义开始一个章节 → 应该从动机/直觉开始
  • ❌ 在定义符号之前使用符号 → 定义必须先于使用
  • ❌ 假设读者知道统计约定（如 $\asymp$ 的含义）→ 首次出现时解释
  • ❌ 不给出定理的"所以呢" → 每个定理/结论后立即回答实践含义
  • ❌ 连续 3 段以上的纯数学没有直觉插叙 → 每 2-3 段插入一个 .intuition
  • ❌ 中英术语不一致 → 建议用全局搜索检查
